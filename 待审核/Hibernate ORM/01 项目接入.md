# Hibernate ORM 项目接入

2026-11-17 待审稿。本文用于比较接入方式和验证首次运行。示例采用 Spring Boot、Maven 和 MySQL，已使用其他环境的项目按相应官方资料调整。

## 1. 搭建前确认 ORM 和接入方式

新建 Java 项目需要 ORM 时，说明候选及推荐理由，向用户明确确认原生 MyBatis、Hibernate ORM 或其他方案。偏向由应用显式编写和控制 SQL 的项目，可评估 MyBatis。需要使用实体状态管理、对象映射或 Jakarta Persistence 接口时，可评估 Hibernate。已有项目如要改选，先核对迁移范围和现有行为。[Java ORM 选型规则](<../../30-40 ORM 编码规范.md#1-项目搭建前确认-orm-选型>) · [MyBatis SQL 映射](https://mybatis.org/mybatis-3/sqlmap-xml.html) · [Hibernate ORM 介绍](https://hibernate.org/orm/)

| 接入方式 | 适合什么时候用 |
| --- | --- |
| Spring Boot + Spring Data JPA | 项目采用 Spring Boot，希望用仓库接口实现常见增删改查。复杂查询仍可按项目约定用 `EntityManager` 或自定义查询。 |
| Jakarta Persistence（JPA）+ Hibernate | 项目希望直接使用 `EntityManager` 管理实体和执行查询。Hibernate 作为 JPA 实现，应用或容器负责持久化单元和事务接入。 |
| Hibernate 原生 API | 确实需要 Hibernate 专属能力时，用 `Session` 等接口，并把专属调用放在数据访问层。确认由谁管理会话和事务。 |

Spring Data JPA 提供数据访问抽象，Jakarta Persistence 定义接口，Hibernate ORM 实现持久化和映射。组合使用时写清每层负责什么，以及哪一套配置管理数据源和事务。[Spring Data JPA](https://docs.spring.io/spring-data/jpa/reference/) · [Jakarta Persistence 规范](https://jakarta.ee/specifications/persistence/)

## 2. 依赖和版本

接入记录写清 Java、构建工具、Spring Boot（若采用）、实际解析到的 Hibernate ORM 和 Jakarta Persistence 版本、数据库及 JDBC 驱动。采用 Spring Boot 时，先用所选 Boot 系列提供的父 POM 或 BOM 管理版本。确需覆盖其管理版本时，核对官方兼容关系并重新验证启动、查询、写入与回滚。[Spring Boot 依赖管理](https://docs.spring.io/spring-boot/reference/using/build-systems.html) · [Hibernate ORM 版本说明](https://hibernate.org/orm/releases/) · [Hibernate ORM 升级指南](https://hibernate.org/orm/documentation/migrate/)

以下片段放进已经使用 Spring Boot 父 POM 或 BOM 的 Maven 项目。`pom.xml` 用于 Maven 构建和依赖管理，示例声明 JPA starter 和 MySQL 驱动。实体映射写在 Java 类的注解中。

```xml
<dependencies>
  <dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-jpa</artifactId>
  </dependency>
  <dependency>
    <groupId>com.mysql</groupId>
    <artifactId>mysql-connector-j</artifactId>
    <scope>runtime</scope>
  </dependency>
</dependencies>
```

查看实际依赖，确保 Hibernate、JPA API 和驱动符合已经确认的版本组合。迁移旧项目时，另核对 `javax.persistence` 到 `jakarta.persistence` 的导包及配置差异。

```text
mvn dependency:tree "-Dincludes=org.hibernate.orm:hibernate-core,jakarta.persistence:jakarta.persistence-api,com.mysql:mysql-connector-j"
```

直接使用 Hibernate 的项目，可从所选系列的官方入门文档确认 `org.hibernate.orm:hibernate-core`、Hibernate BOM、驱动及启动方式。直接接入时另需明确持久化单元或 `SessionFactory` 的初始化和关闭、以及事务边界。[Hibernate ORM 官方入门](https://hibernate.org/orm/documentation/getting-started/)

### 2.1 用注解注册实体

Hibernate 业务实体使用完整的注解映射。表、列、主键、关联以及能用注解准确表达的 DDL 元数据放在实体注解里，具体写法见[实体映射与数据库结构](<02 实体映射与数据库结构.md>)。采用这套方式的新项目无需给每个实体配一个类似 MyBatis Mapper 的 XML，也无需为业务实体编写 `orm.xml` 或 `*.hbm.xml`。版本化的表结构和数据迁移继续由第 3 节的迁移流程管理。

**Spring Boot。** 使用自动配置时，把实体放在启动类所在包或其子包，由 Spring Boot 扫描注册。实体位于其他包时，在现有应用配置中用 `@EntityScan(basePackageClasses = ProductEntity.class)` 指定扫描包；`basePackageClasses` 指定的是扫描范围，按项目实际实体包补齐。`@EntityScan` 的导包以所用 Boot 版本为准。已有 Java 配置自行创建实体管理器工厂时，在相应配置里指定实体包，例如使用对应工厂构建器的 `.packages(ProductEntity.class)`，并核对实体、数据源和事务管理器的对应关系。本文的 Spring Boot 示例无需 `META-INF/persistence.xml`。[Spring Boot 实体扫描](https://docs.spring.io/spring-boot/reference/data/sql.html#data.sql.jpa-and-spring-data.entity-classes) · [指定实体扫描包](https://docs.spring.io/spring-boot/how-to/data-access.html#howto.data-access.separate-entity-definitions-from-spring-configuration) · [自定义实体管理器工厂](https://docs.spring.io/spring-boot/how-to/data-access.html#howto.data-access.use-custom-entity-manager)

**非 Spring Boot。** 应用自己管理持久化单元时，可用 Jakarta Persistence 3.2 的 `PersistenceConfiguration`，例如配合支持该规范的 Hibernate ORM 7.4。把实体通过 `managedClass(...)` 加入配置，再创建 `EntityManagerFactory`，由应用在停机时关闭。这条路线适用于应用管理的持久化单元。下面的 `dataSource` 为应用已准备好的 `javax.sql.DataSource`，工程依赖中已包含 Hibernate 实现和 JDBC 驱动。

```java
EntityManagerFactory entityManagerFactory = new PersistenceConfiguration("product")
        .managedClass(ProductEntity.class)
        .property(PersistenceConfiguration.JDBC_DATASOURCE, dataSource)
        .createEntityManagerFactory();
```

使用 Hibernate 原生引导的项目可用 `MetadataSources.addAnnotatedClass(ProductEntity.class)` 注册，再以构建的元数据创建 `SessionFactory`。按实际版本核对引导 API，并将其他需要管理的类型登记到相应配置中。[Jakarta Persistence 3.2 程序化配置 API](https://jakarta.ee/specifications/persistence/3.2/apidocs/jakarta.persistence/jakarta/persistence/PersistenceConfiguration.html) · [Hibernate ORM 7.4 兼容性](https://hibernate.org/orm/releases/7.4/#compatibility) · [Hibernate ORM 7.4 实体注册 API](https://docs.hibernate.org/orm/7.4/javadocs/org/hibernate/boot/MetadataSources.html#addAnnotatedClass(java.lang.Class))

**已有 XML 的项目。** 先按现有启动配置核对实际加载的映射文件、注解和覆盖后的结果。JPA XML 可覆盖注解，`metadata-complete` 可让相关注解不生效。把存量 XML 转为注解属于单独迁移，需要比较迁移前后的表字段、关联和实际 SQL，并复验原有读写行为。本指南的注解约定不触发自动迁移。[Jakarta Persistence 3.2 第 12 章 XML 映射规范](https://jakarta.ee/specifications/persistence/3.2/jakarta-persistence-spec-3.2.html)

## 3. 数据源与表结构

先选定目标开发或测试库，再把连接信息按环境配置注入。表结构使用项目的版本化迁移脚本维护。下面是由迁移脚本先准备表结构的 Spring Boot 示例。三个环境变量由实际运行入口提供。

```yaml
spring:
  datasource:
    url: ${APP_DB_URL}
    username: ${APP_DB_USER}
    password: ${APP_DB_PASSWORD}
  jpa:
    hibernate:
      ddl-auto: validate
    open-in-view: false
```

- `ddl-auto: validate` 用来检查 Hibernate 所映射的表结构。表结构变更由选定的迁移入口执行，再核对实际列、索引、唯一约束及数据迁移结果。同一目标库使用一套初始化和结构变更流程。需要自动建表的临时试验库单独隔离，按关联映射说明核对生成的 DDL。[无物理外键的关联映射](<02 实体映射与数据库结构.md#2-按查询和写入需要选择关联映射>)
- 按本指南接入的 Spring Boot Web 项目设置 `spring.jpa.open-in-view=false`。Service 在事务内完成所需查询和结果组装，再把 `Vo` 或 DTO 交给页面或接口。按查询指南验证页面渲染和 JSON 序列化阶段的 SQL。[查询与加载](<03 查询与加载.md>)
- 排查连接或映射错误时，先核对实际配置的环境、库名、迁移状态和 JDBC 驱动，再按选定 Hibernate 版本核对方言及数据库支持。Maven 构建 Profile 与运行时数据库环境按项目启动说明对应。

[Spring Boot 数据库初始化](https://docs.spring.io/spring-boot/how-to/data-initialization.html) · [Spring Boot JPA 配置](https://docs.spring.io/spring-boot/reference/data/sql.html) · [开发数据库](<../../10-10 通用开发规范.md#53-开发数据库>) · [Maven 环境 Profile](<../../30-20 Maven 构建与环境规范.md#1-环境-profile>)

## 4. 首次接入验收

1. 用项目的真实启动方式连接隔离数据库，核对生效的环境、库、迁移版本和已注册的实体。使用纯注解接入时，确认应用打包内容和启动配置没有意外加载实体映射 XML。
2. 使用[商品实体示例](<02 实体映射与数据库结构.md>)或项目实体完成一次实际新增并提交，在新的事务中按主键读回记录。核对主键、关键字段及所执行的 SQL。
3. 通过实际业务入口验证一次按条件查询及一次更新失败回滚。涉及数据库方言、约束或并发语义时，使用与目标部署一致的数据库类型和版本验证。
4. 记录实际版本、验证环境、结果和待验证项，再按[查询与加载](<03 查询与加载.md>)及[事务与更新](<04 事务与更新.md>)扩充用例。
