# 实体映射与数据库结构

2026-11-17 待审指南。适用于已确认采用 Hibernate ORM 的 Java 项目，示例使用 `jakarta.persistence` 和 MySQL。Hibernate 的映射与结构校验按项目实际版本验证。MyBatis 专属条款适用于采用 MyBatis 的项目。[指南目录](README.md) · [项目接入](<01 项目接入.md>)

## 1. 按表建立实体

每张表建立一个对应的持久化 `Entity`，包括字典表、关联表和只读查询涉及的表。需要省略时，按 Java 通用规范就具体表名和原因取得用户确认。普通实体类用 `Entity` 后缀，给类和字段写中文说明。下例把注解放在字段上，供持久化框架直接访问字段，并保留 `protected` 无参构造器。页面输入和查询展示按其用途选用对应的对象。[Java 实体约定](<../../30-10 Java 通用代码规范.md#21-每表一个-entity-与命名>) · [Jakarta Persistence 3.2 第 2.1–2.3 节](https://jakarta.ee/specifications/persistence/3.2/jakarta-persistence-spec-3.2.html)

新建实体直接用注解定义映射。类上明确写 `@Entity`、`@Table`，主键字段写 `@Id` 及适用的生成策略，普通持久化字段写 `@Column`。业务实体通过扫描或程序化注册生效，无需为其编写映射 XML。在注解支持的范围内，把与映射相关的 DDL 信息写清楚。[项目接入](<01 项目接入.md>) · [Jakarta Persistence `@Table`](https://jakarta.ee/specifications/persistence/3.2/apidocs/jakarta.persistence/jakarta/persistence/Table.html) · [Jakarta Persistence `@Column`](https://jakarta.ee/specifications/persistence/3.2/apidocs/jakarta.persistence/jakarta/persistence/Column.html)

| 表结构信息 | 在实体里怎样表达 |
| --- | --- |
| 表名、索引、组合唯一约束 | `@Table(name = ...)` 明确表名。需要的索引定义在 `indexes` 中，用 `@Index` 写明名称和列顺序。组合唯一约束用 `uniqueConstraints` 和 `@UniqueConstraint` 定义。 |
| 主键和自增 | `@Id` 标记主键。`@GeneratedValue(strategy = GenerationType.IDENTITY)` 对应插入时由数据库生成的标识。MySQL 默认的有符号 `BIGINT AUTO_INCREMENT` 用 Java `Long` 对应，插入前可为空。 |
| 列名、空值、长度和精度 | 按字段用 `@Column` 声明 `name`、`nullable` 及适用的 `length`、`precision`、`scale`。按 Java 类型和数据库方言核对实际列类型。 |
| 表和字段说明 | 使用 Jakarta Persistence 3.2 时用 `@Table(comment = ...)` 和 `@Column(comment = ...)` 对应数据库的中文注释。旧版按实际 Hibernate 版本核对可用的注释支持，Java 说明和迁移 SQL 保留同一业务含义。 |
| 关联及乐观锁 | 对象关联用适用的关联注解和连接列映射，按[关联映射](#2-按查询和写入需要选择关联映射)关闭物理外键生成。确有并发版本控制时用 `@Version`，并同步列定义。 |

普通列优先用 Java 类型和标准注解表达。确需指定数据库类型时，再用 `columnDefinition`。JPA 3.2 的 `@Column(options = ...)` 用于追加方言相关的 DDL 片段，同一列在这两个写法中选一个。示例使用 Jakarta Persistence 3.2，商品索引对应按供应商筛选并按名称和 ID 排序的查询，实际使用时核对执行计划。[Jakarta Persistence `@Column`](https://jakarta.ee/specifications/persistence/3.2/apidocs/jakarta.persistence/jakarta/persistence/Column.html) · [MySQL 主键规范](<../../40-10 数据库设计规范.md#3-已确认主键默认使用-bigint>) · [MySQL 表和字段注释](<../../40-10 数据库设计规范.md#53-已确认表与字段的中文-comment>) · [查询与加载](<03 查询与加载.md>)

```java
import jakarta.persistence.Column;
import jakarta.persistence.Entity;
import jakarta.persistence.GeneratedValue;
import jakarta.persistence.GenerationType;
import jakarta.persistence.Id;
import jakarta.persistence.Index;
import jakarta.persistence.Table;
import jakarta.persistence.Version;

/** 商品基本资料及其供应商标识。 */
@Entity
@Table(
    name = "product",
    comment = "商品",
    indexes = @Index(name = "idx_product_supplier_name_id", columnList = "supplier_id, name, id"))
public class ProductEntity {

  /** 商品主键，由数据库生成。 */
  @Id
  @GeneratedValue(strategy = GenerationType.IDENTITY)
  @Column(name = "id", nullable = false, comment = "商品主键")
  private Long id;

  /** 商品名称。 */
  @Column(name = "name", nullable = false, length = 100, comment = "商品名称")
  private String name;

  /** 关联供应商的标识，未分配时为空。 */
  @Column(name = "supplier_id", nullable = true, comment = "供应商标识")
  private Long supplierId;

  /** 商品版本，由持久化框架维护。 */
  @Version
  @Column(name = "version", nullable = false, comment = "并发版本")
  private Long version;

  protected ProductEntity() {
  }

  public ProductEntity(String name, Long supplierId) {
    this.name = name;
    this.supplierId = supplierId;
  }

  public Long getId() {
    return id;
  }

  public Long getVersion() {
    return version;
  }

  public void rename(String name) {
    this.name = name;
  }
}
```

示例把商品名列设为必填、容量 100 个字符的文本列。应用仍在实际写入入口按项目约定校验必填和长度，并核对 Java 校验和数据库容量的计量口径。[Java 字段约束与校验](<../../30-10 Java 通用代码规范.md#71-字段约束与校验>) · [MySQL 字段长度与容量](<../../40-10 数据库设计规范.md#71-已确认字段长度与容量>)

示例包含可选的 `@Version`。启用时在 `product` 表安排 `BIGINT NOT NULL` 列，已有记录先由迁移脚本补齐版本值，再启用版本映射及对应的并发控制。持久化框架负责维护该版本，业务代码读取它来处理并发冲突。未采用版本控制的表可以省去版本字段及列。[Jakarta Persistence `@Version`](https://jakarta.ee/specifications/persistence/3.2/apidocs/jakarta.persistence/jakarta/persistence/Version.html) · [事务与更新](<04 事务与更新.md>)

## 2. 按查询和写入需要选择关联映射

**本指南采用无物理外键的设计。** 建表及迁移脚本不创建数据库 `FOREIGN KEY`，Hibernate 对象关联生成 DDL 时也明确关闭相应外键约束。关联 ID、主键、唯一约束和必要索引按业务需要保留。[MySQL 关联规则](<../../40-10 数据库设计规范.md#4-已确认不建立数据库外键>)

**本指南不做懒加载。** 关联优先使用普通 ID 字段，例如 `Long supplierId`。用例需要供应商名称或资料时，由 DAO 或 Service 显式查询并组装。创建或修改关联时，由业务代码校验供应商存在、可用且可被当前操作引用。停用或删除供应商时，按项目约定处理已有引用。需要在并发写入和删除时保证关联完整的场景，还要验证对应的事务和并发控制。[查询与加载](<03 查询与加载.md>)

**关联映射不做级联。** `cascade` 保持空数组，支持 `orphanRemoval` 的关联保持为 `false`。关联记录的新增、修改、删除都由 Service 明确发起。需要维护独立关联表时，通过对应的关联实体显式处理关联记录。[Service 关联写入](<04 事务与更新.md#11-service-显式处理关联写入>) · [Jakarta Persistence 关联规则](https://jakarta.ee/specifications/persistence/3.2/jakarta-persistence-spec-3.2.html#a516)

读取商品实体时固定需要 `SupplierEntity`，且确需由 Hibernate 加载关联对象时，先按查询指南取得人工明确确认。确认后可把上例的 `supplierId` 字段及对应构造参数改为供应商实体，沿用 `supplier_id` 列。同一列只保留一个可写映射。该例显式标注 `FetchType.EAGER`，验收时核对所有受此映射影响的查询。[级联查询的确认要求](<03 查询与加载.md#31-级联查询须经人工确认>) · [Jakarta Persistence `@ManyToOne`](https://jakarta.ee/specifications/persistence/3.2/apidocs/jakarta.persistence/jakarta/persistence/ManyToOne.html) · [Hibernate 实体查询的加载行为](https://docs.hibernate.org/orm/7.4/userguide/html_single/#fetching-direct-vs-query)

```java
// 以下注解来自 jakarta.persistence。
/** 商品关联的供应商。 */
@ManyToOne(fetch = FetchType.EAGER, cascade = {})
@JoinColumn(name = "supplier_id",
    foreignKey = @ForeignKey(ConstraintMode.NO_CONSTRAINT))
private SupplierEntity supplier;
```

`@ForeignKey(ConstraintMode.NO_CONSTRAINT)` 指示 Hibernate 生成 DDL 时省略该连接的物理外键约束。列与对象的映射仍由 `@JoinColumn` 指定。实际数据库结构以已执行的迁移脚本为准。[Jakarta Persistence `@ForeignKey`](https://jakarta.ee/specifications/persistence/3.2/apidocs/jakarta.persistence/jakarta/persistence/ForeignKey.html)

涉及多对多时，先提交项目具体方案并取得用户确认，再建独立关联表和对应实体。比如确认商品与标签的多对多后，`product_tag` 由 `ProductTagEntity` 映射，字段可包括 `id`、`productId`、`tagId`，按业务需要增加关联状态或添加时间。若同一商品和标签只能关联一次，在迁移脚本中建立 `product_id` 与 `tag_id` 的组合唯一约束。参考 Hibernate 手册的关联实体建模，库结构按本指南设计。[MySQL 多对多设计](<../../40-10 数据库设计规范.md#62-已确认明细表与多对多关联表>) · [Hibernate User Guide，第 3.8.4 节的关联实体示例](https://docs.hibernate.org/orm/7.2/userguide/html_single/)

上述唯一约束同时写到关联实体的表映射。列名使用数据库列名，约束名称和列顺序与迁移 SQL 一致。[Jakarta Persistence `@UniqueConstraint`](https://jakarta.ee/specifications/persistence/3.2/apidocs/jakarta.persistence/jakarta/persistence/UniqueConstraint.html)

```java
@Table(
    name = "product_tag",
    uniqueConstraints = @UniqueConstraint(
        name = "uk_product_tag_product_id_tag_id",
        columnNames = {"product_id", "tag_id"}))
```

如商品和标签都必须填写，两列分别写 `@Column(nullable = false)`，在迁移脚本中同步为 `NOT NULL`。上面的约束对应 `product_tag` 建表 SQL 中的 `CONSTRAINT uk_product_tag_product_id_tag_id UNIQUE (product_id, tag_id)`。[MySQL 唯一范围和约束](<../../40-10 数据库设计规范.md#91-已确认唯一范围与唯一约束>)

## 3. 用版本化脚本管理结构

表、字段、索引和约束由项目的版本化迁移脚本维护。注解提供映射和生成 DDL 所用的信息。改动涉及列定义、索引或约束时，同时核对注解、迁移脚本与目标库。数据库专属的默认表达式、引擎、字符集等按项目在 SQL 中定义。下面是与商品实体对应的新库示例。已有库按实际结构编写增量脚本，先核对现有数据和代码读写入口，再决定回填、约束和部署顺序。可在隔离环境生成 DDL 供对照，正式环境按项目流程执行迁移。[开发数据库的版本化脚本](<../../10-10 通用开发规范.md#53-开发数据库>) · [Hibernate User Guide，第 5 节](https://docs.hibernate.org/orm/7.2/userguide/html_single/)

```sql
CREATE TABLE product (
    id BIGINT NOT NULL AUTO_INCREMENT COMMENT '商品主键',
    name VARCHAR(100) NOT NULL COMMENT '商品名称',
    supplier_id BIGINT NULL COMMENT '供应商标识',
    version BIGINT NOT NULL COMMENT '并发版本',
    PRIMARY KEY (id),
    KEY idx_product_supplier_name_id (supplier_id, name, id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='商品';
```

核对迁移 SQL 及用于对照的生成 DDL，确认没有新增 `FOREIGN KEY`。迁移后在目标 MySQL 用 `SHOW CREATE TABLE product` 核对物理外键、主键策略、列类型、空值、约束及注释，用 `SHOW INDEX FROM product` 核对索引列和顺序。用 Hibernate 插入并重新读取一条商品，确认取回主键及字段值。有唯一约束时用重复写入核对约束生效。若映射了对象关联，验证有效关联和无效关联的业务处理，观察实际 SQL。启用版本字段时再覆盖一次版本冲突。[MySQL 查看建表结构](https://dev.mysql.com/doc/refman/8.4/en/show-create-table.html) · [MySQL 查看索引](https://dev.mysql.com/doc/refman/8.4/en/show-index.html) · [事务与更新](<04 事务与更新.md>)
