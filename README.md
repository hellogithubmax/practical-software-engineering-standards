# 实用软件工程规范

Practical Software Engineering Standards

面向实际开发的软件工程规范，强调实用、稳定、易读和好维护。用直白的话说明做法和理由，优先成熟方案，增加复杂度需要有实际收益。

本规范独立维护，使用方自主决定是否采用、怎样引用和如何落地；边界见[仓库维护约定](AGENTS.md#repository-scope)。

## 先看基础，再选专题

`00-00` 是规范总览。其余文件的第一段编号表示分类，第二段表示组内顺序。各组管什么、怎样增补，见[一级分类说明](<00-00 规范总览.md#standard-categories>)。

1. 从[通用开发规范](<10-10 通用开发规范.md>)了解共同原则。
2. 按当前对象的语言、技术和功能选择下面的专题。
3. 需要细化或覆盖时，按[规范总览的适用与继承规则](<00-00 规范总览.md#rule-inheritance>)处理。未覆盖的适用条款继续有效，交叉专题按条件共同采用。

| 分类 | 正文 | 适用范围 |
| --- | --- | --- |
| `10` 基础 | [通用开发规范](<10-10 通用开发规范.md>) | 人工及AI开发、相关工程文档中的共同要求 |
| `20` 开发协作 | [AI 辅助开发规范](<20-10 AI 辅助开发规范.md>) | AI参与的任务，并与适用技术专题共同使用 |
| `20` 开发协作 | [协作开发规范](<20-20 协作开发规范.md>) | 多人开工同步、任务记录、评审和交接 |
| `30` Java | [Java 通用代码规范](<30-10 Java 通用代码规范.md>) | Java 命名、业务与页面目录、注释和排版 |
| `30` Java | [ORM 编码规范](<30-40 ORM 编码规范.md>) | 采用MyBatis-Plus的Java项目 |
| `40` 数据库 | [数据库设计规范](<40-10 数据库设计规范.md>) | MySQL 主键、字段类型与容量设计 |
| `50` 前端 | [前端开发规范](<50-10 前端开发规范.md>) | Web页面、模板、样式和客户端交互 |

| `60` 接口 | [页面与数据接口对接规范](<60-20 页面与数据接口对接规范.md>) | 页面通过数据接口获取或提交数据 |

专题正文注明自身条件，不要求所有项目采用同一套技术。已确认条款和未定材料分别标明，整理文档不自动批准候选。

## 维护入口

- [规范总览](<00-00 规范总览.md>)：层次关系、局部覆盖方法和按问题查阅入口。
- [AGENTS.md](AGENTS.md)：只约定本仓库怎样维护、收录及核对文档。
- [维护记录](维护记录.md)：已确认决定、变更原因及实际调整。
- [待后续处理](待后续处理/AGENTS.md)：已暂存的未定事项和材料，本轮不继续展开。
- [待审核](待审核/AGENTS.md)：以后新增提案的审核入口。
