# 实用软件工程规范

Practical Software Engineering Standards

面向实际开发的软件工程规范，强调实用、稳定、易读和好维护。用直白的话说明做法和理由，优先成熟方案，增加复杂度需要有实际收益。

本规范独立维护，使用方自主决定是否采用、怎样引用和如何落地；边界见[仓库维护约定](AGENTS.md#repository-scope)。

## 先看基础，再选专题

1. 从[通用开发规范](通用开发规范.md)了解共同原则。
2. 按当前对象的语言、技术和功能选择下面的专题。
3. 需要细化或覆盖时，按[规范总览的适用与继承规则](规范总览.md#rule-inheritance)处理。未覆盖的适用条款继续有效，交叉专题按条件共同采用。

| 类别 | 正文 | 适用范围 |
| --- | --- | --- |
| 通用基础 | [通用开发规范](通用开发规范.md) | 人工及AI开发、相关工程文档中的共同要求 |
| 前端领域 | [前端开发规范](前端开发规范.md) | Web页面、模板、样式和客户端交互 |
| Java语言 | [Java 通用代码规范](<Java 通用代码规范.md>) | Java语法、格式、命名和注释细则 |
| Java数据访问 | [ORM 编码规范](<ORM 编码规范.md>) | 采用MyBatis-Plus的Java项目 |
| MySQL数据设计 | [数据库设计规范](数据库设计规范.md) | MySQL表字段设计；Java映射按条件采用 |
| JSON数据格式 | [JSON接口规范](JSON接口规范.md) | 使用JSON交换数据的接口 |
| 页面功能对接 | [页面与数据接口对接规范](页面与数据接口对接规范.md) | 页面通过数据接口获取或提交数据 |
| AI工作方式 | [AI 辅助开发规范](<AI 辅助开发规范.md>) | AI参与的任务，并与适用技术专题共同使用 |

专题正文注明自身条件，不要求所有项目采用同一套技术。已确认条款和未定材料分别标明，整理文档不自动批准候选。
