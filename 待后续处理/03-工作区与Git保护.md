## 候选条款

以下六条是本轮讨论稿，尚未获准采用。

1. **修改前了解工作区状态。** 使用 Git 的项目，先确认当前分支、已有修改和相关差异。工作区有未提交内容，不代表不能继续工作，但要分清哪些是原有内容、哪些是本次修改。
2. **保留已有工作，避免误覆盖。** 同一个文件中已有其他修改时，在其基础上准确调整；不能为了方便，直接用旧版本或重新生成的整份文件覆盖。遇到无法判断的冲突，再说明具体位置。
3. **删除、移动和重命名，按任务需要处理。** 已授权改造所必需的文件调整可以正常执行，同时核对引用、配置和调用关系。无关文件、用途不明的文件，不顺手清理。
4. **可能丢失修改或改写历史的操作，先核实影响和授权。** 例如丢弃未提交修改、大范围清理、改写共享分支历史。不能为了得到“干净工作区”，擅自回退、清空或隐藏已有工作；也不按命令名称一刀切禁止正常操作。
5. **提交、推送和合并，按项目流程及已有授权执行。** 修改代码的授权，不自动等于提交、推送或合并的授权；已经明确授权的操作，不重复确认。
6. **交付前检查最终差异。** 确认本次改动符合任务范围，没有夹带无关格式化、误删除或覆盖；有意保留的既有修改，不计成本次成果。
